# strategy/journal — 交易对账台账

**幻灯片是记录，结单是钱。** 日志只写值得复盘的交易，不是每一笔成交，所以
「29 个持仓对 22 篇复盘」是正常的，不是漏记。台账因此以日志为主轴：日志里每笔
交易都有一行，只有能确认无疑时才挂上持仓数据，日志没提的持仓单独成行。

凡是基于日志行算出来的——胜率、R 倍数、哪个 setup 赚钱——描述的是「被认为值得
写下来的那些交易」，不是这套系统。账户层面的期望值要看 `output/account_days.csv`，
那里每个持仓都在。

把同一批交易的三份记录合成一张表：

| 来源 | 粒度 | 只有它才有的东西 |
|------|------|------------------|
| `data/Trading Analysis Oct 2026.pptx` | 交易想法，每天从 1 编号 | 策略、价位、复盘文字 |
| `data/statements/oct*.pdf` | 成交 | **钱的唯一真相** |
| 幻灯片里的截图 | 交易想法 | **R/R 设计**：止损、目标、比值、周期 |
| `data/journal.csv` | 交易想法 | 手工誊抄（仅 10/07–10/09） |

```bash
uv run strategy/journal/build.py            # -> output/ledger.csv、
                                            #    report.html、report_zh.html
uv run strategy/journal/build.py --crops    # 顺带重切截图
```

## 为什么不能直接 join

**结单日期是交易日，不是自然日。** 每份结单第 6 页写明 20:00–04:00 ET 属于夜盘，
Oct 08 那份的第一笔就在 10/07 20:06。这和日志用的是同一个边界，所以不需要换算——
但一笔在 20:00 之前开、之后平的仓会被劈到两份文件里，所以
`confirmations.positions` 是把库存**跨整个区间串联**的，不是逐份处理。
当前数据里有两笔这样的仓位，分开算会全部丢掉。

**做空一律是买 SOXS，从不裸空 SOXL。** 朴素 FIFO 会把开头那些平仓卖单
读成做空。股数能定论：SOXL 从带入数量起算，中间持仓始终非负且收盘归零。

**不是每笔交易都会被写下来。** `SCRATCH_USD = 2.0` 在做匹配前把小到不值得复盘的
筛掉，但它只是个过滤器，不是规则：扫过 14 种阈值（绝对金额和名义占比），没有一个
能解决超过 28 天里的 16 天。**取舍是判断，不是数值切点。** 没被认领的持仓以
`account only` 留在台账里，因为它们记录的行为有时是一天里信息量最大的部分。

**日志里的一笔是一个想法，不是一个批次。** 10/07 第 4 笔是第 3 笔的加仓。
所以靠胜负序列匹配最多只能唯一定位 26% 的交易，剩下的只有截图里的时间戳能解决
——这就是九月那批截图不是可选项的原因。

**交易编号不是时间顺序。** 日盘是按标的分组的：10/08 的第 6 张是 11:52 那笔
SOXL，而第 7、8 张是更早的两笔 SOXS。所以只有在**笔数、胜负序列、标的序列**
三者同时吻合时才判定匹配，否则写成 `NEEDS REVIEW` 而不是猜。每张裁剪图里保留的
截图时间戳就是人工定序的依据。

## 当前数据的已知缺口

- **10/07** 日志第 4 笔是第 3 笔的加仓（`三次触碰入场加仓`）。账面上这个批次
  亏 $5.38，而日志按合并后的想法记为盈利——这是对的：`+21.20 - 5.38 = +15.82`。
  日志的粒度是想法，账面的粒度是批次。
- **10/08** 有一笔真实仓位（10:56，−13.40）日志里没有。它不是平手单——是当天
  第四大亏损——所以日志的 −85.71 比账面的 −98.51 少算了 13%。
- **10/09** 没有结单，那 6 笔拿不到实际盈亏。
- **九月只有 21 天里的 6 天解析成功。** 每一处失败都是上面两点造成的笔数或顺序
  不符，不是解析问题：月结单对到分（−169.92 对结单的 −169.90，两个标的股数净额
  均为 0），且 21 天里有 19 天与 `daily_win_rate.csv` 吻合在 ±0.02% 内。
- 九月有 6 张幻灯片标题是 `- SOXL, long, open & close, -`：计划了、写了复盘、
  但没进场。保留，无编号无结果。
- 第 10 张幻灯片标题写 SOXS 但图是 SOXL，当天下午也没有 SOXS 仓位；
  `reconcile.SYMBOL_FIXES` 做了修正，10/01 因此才能对上。

## 怎么读输出

`RealizedR` 是账面自己的进出价，对截图上那个止损价量出来的。`-1.0` 表示止损
起了作用，超过就是没守住。`PnL%equity` 用 `EQUITY = 30000`，这个数是从 R/R
工具读出来的——它会打印两种结局下的账户权益。笔记里没提价位的，`Entry` 写 `-`
（写 `NA` 会被当成缺失值读回来）；这类交易的形态放在 `Setup` 列——42 笔里有 13 笔
说的是形态而不是价位。

`ExitMech` 把离场方式标准化了，这是原来单一 `Exit` 列做不到的：
`target`、`trailed stop`、`manual early`、`initial stop`、`stop blown`。
关键区别是前两个——都是盈利出场，但只有一个真的到了这笔交易设计时瞄准的位置。
245 篇复盘里，**116 笔盈利出场只有 59 笔到达了计划的 TP**。
`TargetHit` 是客观版本：`RealizedR >= 0.9 × 计划`。

目前 24 笔完整对账的交易说明：

```
计划 R/R      中位 1.20          24 笔里有 3 笔计划就低于 1.0
实际 R        合计 +8.53R，每笔 +0.355R
计划执行度    盈利单拿到计划的 0.99，亏损单停在 -1.01R
每笔风险      中位 $13.73 = 权益的 0.046%
```

执行几乎是精确的。真正的约束是**计划的尺寸**（中位 R/R 1.20，而当前胜率下的
保本线是 0.81）和**风险单位的尺寸**（0.046%，常规是 0.5–2%）——两者合起来解释了
为什么一个真实的正期望只能产出一条几乎水平的资金曲线。

## 哪些进 git

只有代码和这两份 README，**`data/` 和 `output/` 一律不进**。结单上带着账号和
家庭住址，而这个仓库有远程；其余的也是个人交易记录，同样没有进版本库的理由。

新克隆下来没有 `data/`，`build.py` 会直接报出来。`data/screens.csv` 是这里唯一
脚本重建不了的文件——它是从幻灯片截图手工转录的——所以请和那份 pptx 放在一起
保管，别指望 git。
